Owner of the items that issue #24 (triage of `TODO(phase0)`) and the A1–A5 gates re-tagged `TODO(alpha)` instead of fixing. Each item keeps its own `TODO(alpha) (#<this issue>)` marker in the source or docs; this issue is the single place to schedule them after the alpha. Nothing in this list is a gate condition.

- [x] **Formatter** (`outou fmt`): done (ADR 0011, amendment 2026-10-31, project settings; `crates/outou-fmt/README.md`). (a) cwd and edition: `rustfmt` runs in the formatted file's directory (so its `rustfmt.toml` / `.rustfmt.toml` is found from any cwd) and with the crate's edition from the nearest `Cargo.toml`, following `edition.workspace = true`, else 2021 (`FormatOptions::source_path`, `edition: Option<String>`). (b) `max_width` (and `tab_spaces`, `newline_style`) are read via `rustfmt --print-config current`, defaults 100 / 4 / Auto; `hard_tabs` stays contained to spaces (issue #24). (c) the fit check counts the placeholder's column, the text after it and, in an island, the enclosing indent (the 115-column case now wraps). (d) the island wrapper is dedented by `tab_spaces`. (e) CRLF: normalised in, restored out by `newline_style` (`Auto` keeps the first line ending, so CRLF stays CRLF; `Unix`/`Windows` force one). Remaining small notes are in the crate README (package without `edition` formats as 2021; several JSX expressions on one line count each other as placeholders).
- [ ] **Language server:** rename and references for keyword-named props (`type` to `r#type`, ledger row 29); `prepareRename` on a closing tag returns the opening tag's range (done: the request's cursor now picks the closing tag's own range, `crate::rename::translate_prepare_rename_response`; the rename still edits both tags); URIs are normalised on disk (symbolic links, `..`, percent-encoding) but not per full RFC 3986 (`file://localhost/`, UNC paths, non-`file:` schemes), and Windows drive-letter URIs are not handled (the symbolic-link case was reproduced in a real editor and fixed, see `docs/alpha-results.md` F17); tag and attribute-name completion re-parses every `.rsx` file per key (L15); `textDocument/formatting` runs synchronously with no deadline and ignores `options` (done: it now has a 10 second budget covering all `rustfmt` processes, past which `rustfmt` is killed and the request fails with `RequestFailed` "Outou formatting timed out"; `options` are ignored on purpose, `rustfmt.toml` stays the source of truth as for `outou fmt`, pinned by a test, see `crates/outou-lsp/README.md`); (done: `Workspace::replan` is transactional, the new state is built aside and swapped in only when every unit generated, so a failed re-plan keeps the previous plan, documents and units; external edits to files that are not open are picked up through `workspace/didChangeWatchedFiles`, see F17 below.) Open: a plan error such as `mod x;` with no `x.rsx` is never shown in the editor, in either re-plan path (a `.rsx` edit or a watched-file event); it only reaches the server's stderr. The real fix is a diagnostic on the declaring `mod` item. Also open: the startup `didOpen` to rust-analyzer (`crates/outou-lsp/src/server.rs` ~460-472) sends version 1 but never sets `unit.ra_version = 1`, so the first `didChange` also carries version 1 (rust-analyzer tolerates it today).
- [ ] **Grammar and parser:** `#[react_import]` payload (React interop phase); fragments (`<>`); whether `< span/>` (a space after `<`) is accepted as an element in child position, as it is at the top level.
- [x] **Diagnostics wording:** "Phase 0" appeared in user-facing messages (`crates/outou-modules/src/error.rs`, `crates/outou-syntax/src/parser/diag.rs`). Fixed: the five unsupported-syntax messages now read "... are not supported" and the module messages say "Outou does not evaluate `cfg`" and "Outou requires module files under the crate root"; fixtures, `docs/grammar.md` and tests updated, and unit tests assert that no message contains "Phase 0".
- [x] **Front-end warnings** (such as the `<select>` warnings) were shown by `outou check` and the language server but not by `outou build` or `outou cargo`. Fixed (ledger row 56): both now print them to standard error in `outou check`'s format, on every run (also when nothing is rewritten), and they never change the exit code.
- [x] **Children:** `&String`, `&&str`, `Arc<str>`, `Rc<str>`, `Cow<str>`, `Box<str>`, `Option<number>` (and `Option<char>`, `Option<&number>`) and iterators of text (`&str`, `String` and those pointer types as items) are children. Left: an iterator of numbers is still not a child (map each item to text); `Option<bool>` stays an error: ADR 0014 decides `bool` is not a child, and `Option<bool>` follows from the `T: IntoChild<Displayed>` bound (ledger rows 42 and 57).
- [ ] **Windows** is out of scope for the alpha (see `crates/outou-cli/README.md`).
- [x] **Known test flakes:** `fmt::tests::run_calls_format_source_exactly_once_per_changed_file` (ETXTBSY) and the timing tests in `outou-syntax`'s perf suite under load. Fixed: the perf ratio tests compare parse time at N and 4N using the best of 7 runs and fail only above 10x (linear is about 4x, quadratic about 16x), with arithmetic self-checks of the ratio rule; the fmt test retries until the fake rustfmt script has actually started, since an ETXTBSY exec never runs it. Left as-is: the absolute-bound tests (`assert_parses_within` in `crates/outou-syntax/tests/item_recovery.rs` and `long_path_is_linear` in `crates/outou-syntax/tests/perf.rs`) did not flake. Not yet flaky and not fixed: other tests that write a script and then exec it without an ETXTBSY retry (`crates/outou-lsp/tests/ra_stderr.rs`, `crates/outou-lsp/src/dispatch/progress_tests.rs`, `crates/outou-cli/tests/cargo_cli.rs`).
- [ ] **Other known gaps recorded in the ledger:** `r#key` and other raw identifiers in JSX attribute names are not normalised (done: `r#name` is the same attribute as `name`, `r#key` is the typed `key`, via `outou_syntax::ast::unraw_name`; ledger row 58, `docs/grammar.md` §5.1); `bare_rust_expr` treats a semicolon-free multi-statement attribute island as one expression (done: it uses the child side's `expr_shape` rule, so `attr={ if c {} "x" }` keeps its braces and compiles as the block it reads as; ledger row 58); the case-insensitive-filesystem stale-file cleanup bug in `outou build` (`docs/alpha-results.md` A1 (f), from issue #20) (done: `clean_stale` probes whether the generated directory's filesystem folds case and, if so, compares names lower-cased, so a file rewritten under a differently-cased name is kept and respelled to the produced name; `crates/outou-cli/src/build/clean.rs`). Remainder, not done: Unicode normalisation (APFS treats NFC and NFD `café.rs` as one file), so a non-ASCII module name can still hit the original deletion (`TODO(alpha) (#31)` in `clean.rs`).
- [ ] **Existing `TODO(alpha)` markers in the ledger** (`docs/backend-leakage.md` rows 35, 37, 38, 39, 40, 41, 42, 43 and 45): each row's open question is owned by this issue, see ledger row 50. Rows are not rewritten.
- [ ] **State/Signal misuse messages:** the vocabulary of the errors for a `State<T>` or `Signal<T>` used as a child where `T` is not renderable, and for a non-`Send` state (`docs/alpha-results.md` A5, rows 42 and 45(b)); the wording is not yet Outou's.
- [x] **`outou fmt` writes in place, not atomically:** a failure part-way through the write (a full disk, reproducible with `ulimit -f`) can leave a `.rsx` file truncated. A temporary file next to the resolved target plus a rename fixes it and keeps a symlinked file a symlink. Fixed: `outou fmt` and `outou build` share `crates/outou-cli/src/atomic_write.rs` (temp file beside the resolved target, permissions copied, rename, temp removed on failure).
- [ ] **Attribute names (ledger row 12, row 51):** the language server completes attribute names from a small hand-written table (`crates/outou-lsp/src/html_attrs.rs`, names read from `dioxus-html 0.7.10`); it is not generated from the HTML specification, nothing checks an attribute name written in a `.rsx` file against it, `data-*` has no completion and attribute values (`type="..."`) get none. A complete, spec-derived table, validation of names in Outou's own diagnostics, and value completion belong here.
- [ ] **Language server in a real editor (F17, 2026-10-25, ledger row 53):**
  - [x] (a) The Output channel "Outou Language Server" shows rust-analyzer's whole standard error (`WARN overly long loop turn ...`, `PrimeCaches`, the full text of each `didSave`, which is the generated Rust and its `.generated` path), every line at `[error]` level. This leaks generated code and backend vocabulary to the user. `TODO(alpha) (#31)`: drop it by default, show it when an environment variable asks for it, or lower it to a suitable level. Fixed (ledger row 54): dropped by default, `OUTOU_LSP_RA_LOG=1` passes it through, and the extension shows server stderr at `[info]`. Confirmed in a real editor (2026-10-25, workspace opened through a symbolic link, ledger row 55).
  - [x] (b) rust-analyzer's own `non_snake_case` diagnostic shows as a warning on `#[component]` functions (``Function `TaskList` should have snake_case name``). Fixed (ledger row 54): codegen writes `#[allow(non_snake_case)] ` before a PascalCase `#[component]` function. Confirmed in a real editor (2026-10-25): no warning on `TaskList` or `TaskRow`.
  - [x] (c) Opening a `.rsx` file that already has flycheck diagnostics published an empty set, which stayed until the next save. Fixed: the server already stored rust-analyzer's latest diagnostics per generated unit (it opens every unit on rust-analyzer at startup, so they arrive whether or not the `.rsx` file is open); `didOpen` regenerated the unit and cleared them. Now they are kept, and no redundant `didChange` is sent to rust-analyzer, when the regenerated text is identical; any edit that changes the generated text still clears them (they describe the old text). Covered by unit tests only (`opening_a_file_with_unchanged_text_keeps_the_stored_rust_analyzer_diagnostics`); not re-checked in a real editor.
  - (d) rust-analyzer's file-watch globs use the real path, so in a workspace opened through a symbolic link, on-disk `.rs` changes may not reach it (a guess, not checked). Separate from this guess, external edits to `.rsx` files that are not open are now handled by the server itself: it registers `**/*.rsx` and `**/Cargo.toml` watchers after the handshake (when the client supports dynamic registration) and handles `workspace/didChangeWatchedFiles` (created, changed and deleted closed files are re-read and their diagnostics republished or cleared; open buffers win). Not yet confirmed in a real editor: after `git checkout`, the old diagnostic should disappear without `Cmd+S`.
  - (e) Non-`file:` schemes, Windows and `file://localhost/` URIs (see "Language server" above).
