Owner of the items that issue #24 (triage of `TODO(phase0)`) and the A1–A5 gates re-tagged `TODO(alpha)` instead of fixing. Each item keeps its own `TODO(alpha) (#<this issue>)` marker in the source or docs; this issue is the single place to schedule them after the alpha. Nothing in this list is a gate condition.

- [x] **Formatter** (`outou fmt`): done (ADR 0011, amendment 2026-10-31, project settings; `crates/outou-fmt/README.md`). (a) cwd and edition: `rustfmt` runs in the formatted file's directory (so its `rustfmt.toml` / `.rustfmt.toml` is found from any cwd) and with the crate's edition from the nearest `Cargo.toml`, following `edition.workspace = true`, else 2021 (`FormatOptions::source_path`, `edition: Option<String>`). (b) `max_width` (and `tab_spaces`, `newline_style`) are read via `rustfmt --print-config current`, defaults 100 / 4 / Auto; `hard_tabs` stays contained to spaces (issue #24). (c) the fit check counts the placeholder's column, the text after it and, in an island, the enclosing indent (the 115-column case now wraps). (d) the island wrapper is dedented by `tab_spaces`. (e) CRLF: normalised in, restored out by `newline_style` (`Auto` keeps the first line ending, so CRLF stays CRLF; `Unix`/`Windows` force one). Remaining small notes are in the crate README (package without `edition` formats as 2021; several JSX expressions on one line count each other as placeholders).
- [ ] **Language server:** rename and references for keyword-named props (`type` to `r#type`, ledger row 29); `prepareRename` on a closing tag returns the opening tag's range (done: the request's cursor now picks the closing tag's own range, `crate::rename::translate_prepare_rename_response`; the rename still edits both tags); URIs are normalised on disk (symbolic links, `..`, percent-encoding) but not per full RFC 3986 (`file://localhost/`, UNC paths, non-`file:` schemes), and Windows drive-letter URIs are not handled (the symbolic-link case was reproduced in a real editor and fixed, see `docs/alpha-results.md` F17); tag and attribute-name completion re-parses every `.rsx` file per key (L15); `textDocument/formatting` runs synchronously with no deadline and ignores `options` (done: it now has a 10 second budget covering all `rustfmt` processes, past which `rustfmt` is killed and the request answers `null` and logs one line to stderr, never an error response; `options` are ignored on purpose, `rustfmt.toml` stays the source of truth as for `outou fmt`, pinned by a test, see `crates/outou-lsp/README.md`); (done: `Workspace::replan` is transactional, the new state is built aside and swapped in only when every unit generated, so a failed re-plan keeps the previous plan, documents and units; external edits to files that are not open are picked up through `workspace/didChangeWatchedFiles`, see F17 below.) (done: a plan error such as `mod x;` with no `x.rsx` is now an Error diagnostic (source `outou`, the wording `outou build` prints) on the declaring `mod` item, in both re-plan paths (a `.rsx` edit and a watched-file event), merged into the same `publishDiagnostics` as that file's syntax and rust-analyzer diagnostics (`Workspace::plan_error`, `crates/outou-lsp/src/documents/plan_error.rs`); the declaring file is usually `.rsx` but may be a plain `.rs` file, and the diagnostic is then published on the `.rs` file; the location is the `declared_in` and `span` every `ModuleError` already carried (leading whitespace and comments skipped), so no change to `outou-modules` was needed; an error that names no `mod` item is shown at 0:0 of the crate root file; the edited unit is still regenerated against the plan in force and sent to rust-analyzer while the error stands; the error clears on the next successful re-plan, which any `.rsx` edit while an error exists triggers, as do closing a `.rsx` buffer (re-planned from disk), saving a `.rs` file (`**/*.rs` is not watched because the server's own `.generated/*.rs` writes would trigger it) and watched-file events; left: a plan error at startup (the server then runs in degraded mode and never re-plans out of it, so such a diagnostic could not be cleared) and on `.rsx` save, which only repeats an error the edit already showed); (done: the startup `didOpen` to rust-analyzer now records the version it sends as `unit.ra_version = 1`, so the first `didChange` carries 2, `startup_did_open_params` in `crates/outou-lsp/src/server.rs`, sharing `INITIAL_RA_VERSION` with the `didOpen` of a newly planned unit). Confirmed in a real editor on 2026-11-07 (ledger row 60): `mod missing;` typed unsaved in `main.rsx` showed an Error on that `mod` line, hover and completion kept working while editing elsewhere in the file, deleting the line cleared the error, and typing it again then closing the tab without saving left no stale error. (done, D4: single-unit `regenerate` looked `PlannedUnit::module_paths` up by the byte offset of each `mod` declaration, so typing a line above `mod a;` dropped its `#[path]` rewrite from the text sent to rust-analyzer; reproduced for every layout: the mirrored layout lost `#[path = "a.rs"]` (harmless in practice only because the bare `mod a;` finds the same file), a `#[path = "sub/util.rsx"]` module kept its original attribute so rust-analyzer looked for a missing `.generated/sub/util.rsx` (rustc: `couldn't find file`), cfg-duplicated `mod imp;` declarations kept their `.rsx` paths instead of `imp.rs` and `imp-1.rs`, and a nested `mod b;` in `a.rsx` and same-named modules in different inline blocks lost theirs; now `Workspace::regenerate` re-keys the plan's map onto the edited text by declaration order (`crate::plan::rekey_module_paths`: the n-th `mod` stays the n-th while `declared_modules` is unchanged; that check now includes each declaration's nesting depth, so the pre-order list fixes the declaration tree, and moving a `mod` into or out of an inline module, or deleting a brace so that nesting changes, now re-plans, the latter showing a transient but accurate plan error; it is the same check that sends a changed module set to a re-plan), while the plan, `outou build` and the offset key of `GenerateOptions::module_paths` are untouched; left: an edit that could not be re-planned (`Workspace::plan_error`) and also changes the module set is still regenerated with the plan's offsets, as before). Open (D6, older than this change): the module-shape check ignores conditional path attributes, so typing `#[cfg_attr(unix, path = "a.rsx")]` above `mod a;` does not re-plan and the plan error "conditional module path is not supported" is never shown. Open (D5): watched-file change events for `.rsx` files outside the plan are ignored, so fixing such a file on disk does not clear an error shown on it until the next re-plan.

- [x] **Diagnostics wording:** "Phase 0" appeared in user-facing messages (`crates/outou-modules/src/error.rs`, `crates/outou-syntax/src/parser/diag.rs`). Fixed: the five unsupported-syntax messages now read "... are not supported" and the module messages say "Outou does not evaluate `cfg`" and "Outou requires module files under the crate root"; fixtures, `docs/grammar.md` and tests updated, and unit tests assert that no message contains "Phase 0".
- [x] **Front-end warnings** (such as the `<select>` warnings) were shown by `outou check` and the language server but not by `outou build` or `outou cargo`. Fixed (ledger row 56): both now print them to standard error in `outou check`'s format, on every run (also when nothing is rewritten), and they never change the exit code.
- [x] **Children:** `&String`, `&&str`, `Arc<str>`, `Rc<str>`, `Cow<str>`, `Box<str>`, `Option<number>` (and `Option<char>`, `Option<&number>`) and iterators of text (`&str`, `String` and those pointer types as items) are children. Left: an iterator of numbers is still not a child (map each item to text); `Option<bool>` stays an error: ADR 0014 decides `bool` is not a child, and `Option<bool>` follows from the `T: IntoChild<Displayed>` bound (ledger rows 42 and 57).
- [ ] **Windows** is out of scope for the alpha (see `crates/outou-cli/README.md`).
- [x] **Known test flakes:** `fmt::tests::run_calls_format_source_exactly_once_per_changed_file` (ETXTBSY) and the timing tests in `outou-syntax`'s perf suite under load. Fixed: the perf ratio tests compare parse time at N and 4N using the best of 7 runs and fail only above 10x (linear is about 4x, quadratic about 16x), with arithmetic self-checks of the ratio rule; the fmt test retries until the fake rustfmt script has actually started, since an ETXTBSY exec never runs it. Left as-is: the absolute-bound tests (`assert_parses_within` in `crates/outou-syntax/tests/item_recovery.rs` and `long_path_is_linear` in `crates/outou-syntax/tests/perf.rs`) did not flake. Not yet flaky and not fixed: other tests that write a script and then exec it without an ETXTBSY retry (`crates/outou-lsp/tests/ra_stderr.rs`, `crates/outou-lsp/src/dispatch/progress_tests.rs`, `crates/outou-cli/tests/cargo_cli.rs`).
- [ ] **Other known gaps recorded in the ledger:** `r#key` and other raw identifiers in JSX attribute names are not normalised (done: `r#name` is the same attribute as `name`, `r#key` is the typed `key`, via `outou_syntax::ast::unraw_name`; ledger row 58, `docs/grammar.md` §5.1); `bare_rust_expr` treats a semicolon-free multi-statement attribute island as one expression (done: it uses the child side's `expr_shape` rule, so `attr={ if c {} "x" }` keeps its braces and compiles as the block it reads as; ledger row 58); the case-insensitive-filesystem stale-file cleanup bug in `outou build` (`docs/alpha-results.md` A1 (f), from issue #20) (done: `clean_stale` probes whether the generated directory's filesystem folds case and, if so, compares names lower-cased, so a file rewritten under a differently-cased name is kept and respelled to the produced name; `crates/outou-cli/src/build/clean.rs`). - [x] **State/Signal misuse messages:** the vocabulary of the errors for a `State<T>` or `Signal<T>` used as a child where `T` is not renderable, and for a non-`Send` state (`docs/alpha-results.md` A5, rows 42 and 45(b)); the wording is not yet Outou's. Done (ledger row 59): a `State<T>` child with an unrenderable `T` has the facade's message and a `State`-specific note (`Clone` clause added); a `State` captured by a `Send`/`Sync` closure is rewritten by `outou cargo` (and the language server) to ``a `State` cannot be sent to or shared with another thread`` with the storage-cell notes dropped, and one captured by a future that must be `Send` keeps rustc's message with the `State` note added. `Signal<T>` is not nameable from the prelude, so there is nothing to word. - [x] **`outou fmt` writes in place, not atomically:** a failure part-way through the write (a full disk, reproducible with `ulimit -f`) can leave a `.rsx` file truncated. A temporary file next to the resolved target plus a rename fixes it and keeps a symlinked file a symlink. Fixed: `outou fmt` and `outou build` share `crates/outou-cli/src/atomic_write.rs` (temp file beside the resolved target, permissions copied, rename, temp removed on failure).
- [ ] **Attribute names (ledger row 12, row 51):** the language server completes attribute names from a small hand-written table (`crates/outou-lsp/src/html_attrs.rs`, names read from `dioxus-html 0.7.10`); it is not generated from the HTML specification, nothing checks an attribute name written in a `.rsx` file against it, `data-*` has no completion and attribute values (`type="..."`) get none.
