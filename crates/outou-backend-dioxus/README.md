# outou-backend-dioxus

Temporary Dioxus backend. Emits `rsx!` invocations as text through `::outou::__private`.
Does not depend on Dioxus itself; user crates never depend on Dioxus directly.

Phase 0: Week 4 (Gate 2).

## Lowering rules

- `#[component] fn Name(...) -> Element { ... }`, or any other function: attributes (`#[component]` included — a backend-neutral marker, not a codegen switch) and the signature are copied verbatim; only the body's JSX is lowered. JSX inside a non-component function, an `impl`/`trait` method body, or any other item-level Rust (`Item::Rust`) is lowered exactly the same way.
- A JSX element in expression position (a statement, a tail, or inside an island) becomes `::outou::__private::rsx! { … }`.
- Elements and components share one lowering path (`Name { attr: value, …, children }`): Dioxus's `rsx!` decides "component" vs. "element" from the identifier's first letter, the same rule Outou's grammar uses, so codegen never branches on it. A nested element (a child of another element) is written without its own `rsx!` wrapper, since it is already inside one.
- Attribute names that are a plain Rust identifier (not a Rust keyword) are written as `name: value`; a hyphenated name (`data-id`) or one that is a Rust keyword (`type`, `for`, …) — both legal per grammar §5 but not legal Rust field-key identifiers — is written with Dioxus's raw string-key syntax, `"name": value` (`docs/backend-leakage.md` row 14).
- A bare attribute (`<input disabled />`) is boolean: `disabled: true` (grammar §5.1, not additional grammar).
- An attribute's string value and a text child are both Rust string literals; since Dioxus's `rsx!` treats every string literal as an interpolated format string, a literal `{`/`}` byte is doubled to `{{`/`}}` before splicing (`docs/backend-leakage.md` row 15; not observable through Outou's own grammar today, since raw `{`/`}` cannot appear in `JsxText`, but this is the rule codegen itself must follow).
- An event attribute (`onclick={handle_click}`) is not special syntax: it lowers exactly like any other expression attribute (`docs/backend-leakage.md` row 9 already covers handler types being Dioxus's).
- An island (`{ … }`, in a child or an attribute value) reproduces its own braces and lowers its content part by part, so a JSX element nested inside an `if`/`match`/closure becomes its own `rsx! { … }` call and the island keeps whatever type Dioxus needs there (`Element`, `bool`, an iterator, …).
- A file-based module (`mod name;`) whose name is a key of `GenerateOptions::module_paths` gets its `#[path]` attribute rewritten (attributes and qualifiers otherwise preserved verbatim); one absent from the map, or an inline module (`mod name { … }`, which has no file of its own), is left as-is except for the JSX inside it.
- Doc comments and `#[cfg(test)]` are preserved verbatim: both are ordinary Rust source slices (attributes, or plain `Item::Rust`/`RustItem` content), never specially recognized or stripped by this crate.
- Every generated file starts with `// Generated by Outou from <source>. Do not edit.`. No `#![allow(...)]` is emitted — this crate never weakens lints to make generated output pass them (`AGENTS.md`); what `cargo clippy` reports for the generated example app is issue #8's concern.

## Recovery-mode placeholders

`Mode::Recovery` output is for rust-analyzer only. It is never fed to `rustc` through `cargo build` — `outou_codegen::reject_syntax_errors_in_strict_mode` refuses `Mode::Strict` generation whenever a broken construct could occur, so a backend's `Mode::Strict` path never actually has to lower an `ast::ErrorNode`. A placeholder therefore only has to *type-check*, never to run: `outou::__private::recovery()`/`recovery_element()` both `unreachable!()` if a bug ever called them.

- **A JSX element whose opening tag never recovered a name** (grammar §9: a fragment `<>`, a stray closing tag, …) is replaced wholesale by `::outou::__private::recovery_element() -> Element`, since there is no element syntax (`Name { … }`) to reconstruct at all.
- **A JSX element whose opening tag has a name but never reached `>`** (e.g. `<div cl` cut off by end of file) is *not* replaced: its name and whatever attributes/children were recovered are still known, so it lowers as ordinary element syntax (`div { cl: true, }`). A missing or mismatched closing tag never forces the placeholder either — Dioxus's own `rsx!` closes an element with a synthesized `}`, never a textual closing tag, so `close` only ever contributes an *extra* source span for the name's mapping, never a reason to give up.
- **A broken attribute value** (an unterminated string or island) is dropped along with its whole attribute (name included), rather than kept as `name: recovery()`: there is no safe way to know what type `recovery()` should have been inferred as for an attribute Dioxus itself has to validate, and dropping it keeps the surrounding element free of an attribute typed against the wrong shape while the user is still typing.
- **A broken Rust expression** (a statement, tail, or island `ErrorNode`, not currently produced by the parser for any required fixture, but handled defensively) becomes `::outou::__private::recovery()`, whose type is inferred from context (no turbofish — `recovery` is a plain generic function; LOW-15, issue #6 fix list item 12).
- **A function whose signature never reached a body or a body-less `;` before end of input** (its parameter list itself is truncated mid-token) cannot be reconstructed as a valid Rust item at all — there is no parameter list to complete. The parser does not always diagnose this shape as an error: a body-less `fn App(` mid-file can swallow the rest of the file into its own signature text with *zero* diagnostics (CRITICAL-1, issue #6), so `Mode::Strict` cannot rely on being refused before reaching codegen — it splices the function's whole span verbatim instead of dropping it, so `rustc` reports the real error (an unclosed delimiter) at the right place rather than silently compiling a file with the rest of it missing. `Mode::Recovery` instead keeps the *symbol* (MEDIUM-14, issue #6 fix list item 7): `fn <Name>() -> ::outou::__private::Element { ::outou::__private::recovery() }`, name mapped to `function.name.span`, so it stays resolvable in the outline, in completion and at every use site; the original attributes (`#[component]` included) are dropped, since they need a coherent signature to mean anything. A *swallowed* mid-file tail can still take following items with it before this function ever gets a chance to help — `bodyless-fn-mid-file.rsx` and `unclosed-island-mid-file.rsx` (`tests/recovery.rs`) exercise exactly this — but that swallowing is the parser's own element/signature recovery (issue #4), not something this crate's codegen causes or can fix (LOW-17, issue #6 fix list item 12).
- **A block that reached end of input without its own closing `}`** (grammar §2.2's Rust-level recovery) gets one synthesized by codegen, so the generated file stays balanced. This is the mechanism, together with the previous two rules, that makes every fixture under `tests/fixtures/incomplete/` produce a complete, `syn`-parseable Rust file (`tests/recovery.rs`).

## Tests

- `tests/golden.rs`: `examples/phase0-app`'s two `.rsx` files and every `tests/fixtures/formatting/*/input.rsx` fixture, generated in Strict mode and compared byte-for-byte against `tests/golden/<name>/{expected.rs,expected.map.json}`. Regenerate with `BLESS=1 cargo test -p outou-backend-dioxus --test golden` and review the diff.
- `tests/recovery.rs`: every `tests/fixtures/incomplete/*.rsx` fixture, generated in Recovery mode, parses as Rust (`syn`, a dev-only dependency — a fast but weak check, see the module doc) and still contains every complete Rust expression from the input, verbatim. `every_incomplete_fixture_compiles_with_no_parse_errors` (`#[ignore]`d by default, same reason as `tests/compile_check.rs`) is the real compile gate: it `cargo check`s each fixture's recovery output in a throwaway crate and asserts no *parse* error (type/name-resolution errors are permitted, since recovery output only has to stay analyzable, never to type-check).
- `tests/source_map.rs`: a component's name maps back to both its opening and closing tag; text and attribute names get the right `MappingKind`; the `rsx!` invocation site itself maps back to the element's span.
- `tests/compile_check.rs` (`#[ignore]`d by default — see its module doc): writes the generated example app into a throwaway crate under `target/` with `outou` as a path dependency and runs `cargo check` on it.
- `tests/splice.rs`: for every fixture under `tests/fixtures/{formatting,incomplete,modules}` and `examples/phase0-app`, `Mode::Strict` output must never drop a byte of source outside a JSX element's own span (the regression test for CRITICAL-1).
